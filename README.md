# Машина сборки КП — админка (операционная часть)

Операционная половина демо машины автоматической сборки коммерческого предложения (КП / BP) по внутреннему ТЗ BP auto-assembly (30.09.2026): менеджер собирает КП в конструкторе — машина считает арифметику, ведёт документ по маршруту блоков и проверяет ворота.

**Смотреть: <https://ivanmetel.github.io/meleshin-bp-admin/>**
**ЛК клиента (опубликованное состояние): <https://ivanmetel.github.io/meleshin-bp-client/>**

Все данные демо вымышлены: объект 2699-Limassol-Apartment, суммы, участники и контакты не существуют. Сборка целиком в браузере, без сервера; правки манифеста живут в памяти страницы до перезагрузки.

## Связь с ЛК клиента

Движок и данные живут в этом репо; ЛК клиента (meleshin-bp-client) грузит их отсюда и рендерит **опубликованное** состояние:

- **published.json** — состояние, опубликованное клиенту (манифест + вариант + статус). ЛК грузит его по умолчанию: правка данных в админке и push меняют клиентскую страницу без дублирования кода;
- **«Предпросмотр ЛК клиента ↗»** — открывает ЛК с текущим состоянием конструктора, переданным в адресе (`#preview=…`): правки манифеста, варианта и решений видны в ЛК сразу, до публикации.

## Виды админки

- **Собрать** (главный экран, ТЗ Админка 02.10) — собранный клиентский документ: карточка ЛК в центре (экран = PDF, 794 px), рельс разделов слева (человеческие имена + статусы данных), инспектор справа — источник нажатого элемента: строка сметы (склейка помещений), фиксированный блок ТЗ или редактируемое поле; числа раскрывают арифметическую лестницу. Состав работ read-only — приходит из сметы;
- **Проверить** — отчёт машины: сборка, агрегация, арифметика, ворота 1–10; ворота с якорем ведут к месту в документе;
- **Отправить** — статус (Отправлен / Согласован с клиентом) и публикация (в демо — push published.json).

Верхняя панель: объект и дата КП, режимы Собрать / Проверить / Отправить.

## Модель

```
манифест (оператор)  →  машина (агрегация, арифметика, маршрут блоков, ворота 1–10)  →  документ (слайды + markdown)
```

- Оператор ничего не перепечатывает: манифест — указатели на источники плюс коммерческие значения и переключатели макета.
- Машина не сочиняет текст: каждая фраза документа — либо фиксированный блок шаблона, либо значение из источника.
- Один факт — один носитель: состав работ живёт только в таблице работ; ворота 9 проверяют это механически.
- Встроенный калькулятор: каждое число — арифметика показанных строк; ручных чисел в интерфейсе нет.

## Файлы

| Файл | Назначение |
|:--|:--|
| `index.html` | каркас админки (топбар, панель сборки, рельс / документ / инспектор) |
| `styles.css` | стили: палитра, конструктор «Собрать», таблицы документа, отчёт |
| `data.js` | фиксированные блоки ТЗ (дословно), демо-строки работ и материалов, манифест по умолчанию |
| `engine.js` | движок: варианты, агрегация, сборка, ворота, клиентские представления — общий код админки и ЛК |
| `admin.js` | экран «Собрать» (рельс, инспектор, дифф вариантов), «Проверить», «Отправить»; связь с ЛК |
| `published.json` | опубликованное для клиента состояние — источник ЛК по умолчанию |

## Запуск

Опубликовано — открывать в браузере. Локально (для правок рабочей копии): статические файлы, любой локальный сервер — `python3 -m http.server 8080`. ЛК клиента локально указывает на админку параметром: `…meleshin-bp-client/?admin=http://localhost:8080/`.
